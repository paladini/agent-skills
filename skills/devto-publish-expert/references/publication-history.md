# Publication history manager

For a workflow using this JSON history format, use `scripts/publication_history.py` for every history write. The script uses the Python standard library. On Windows, use `py -3` if `python` is unavailable. It never fetches GitHub or DEV itself.

```
py -3 scripts/publication_history.py --state HISTORY.json check
py -3 scripts/publication_history.py --state HISTORY.json append --input UPDATE.json
py -3 scripts/publication_history.py --state HISTORY.json rotation --inventory INVENTORY.json --candidate owner/repo
```

Run `check` during preflight, before publishing. An error blocks publication; do not bypass the script. For `append`, write a temporary UTF-8 JSON object with `articles` and/or `runs` arrays and optional string `lastReconciledAt`. New article records require a positive `articleId` or `devtoArticleId`; the manager writes `devtoArticleId` and, when a URL is supplied, `devtoUrl`, retaining the supplied fields. Each new run needs a unique `runId`; reuse the same ID for retries of the same run. It refuses conflicting existing fields instead of guessing how to merge them. Reconcile such conflicts manually without losing records. For an automatically published article, use `source: "automation"`, local `publishedOn` in YYYY-MM-DD and its `https://dev.to/` URL so downstream consumers can find it. Preserve status, repository and other workflow-required metadata. Never put credentials, article bodies or full tool responses in updates.

The manager validates UTF-8, JSON, title size, new-field size and total size; writes and validates a sibling temporary file; creates a verified managed backup; atomically replaces the state; and retains the three newest backups it manages. Legacy backups are untouched. It uses a separate exclusive write lock. If that lock remains after a crash, investigate ownership and remove it only when no writer is active. The workflow's outer run lock is still required across research, publication and state updates. The output reports before/after bytes; flag unexpected increases in the final report. An unusually large increase blocks a write.

Before selecting and again before publishing, create an inventory JSON from a complete fresh GitHub inventory and all public DEV articles. It must contain `inventoryComplete: true`, `articlesComplete: true`, `unresolvedArticles: []`, `eligibleRepositories` and `coveredRepositories` arrays of `owner/name` strings. Only assert completeness after checking pagination and eligibility; include repositories covered by any matching public article, not just automated articles. If any article that could cover a project cannot be mapped confidently, put its ID in `unresolvedArticles` and stop for review. A genuine non-project article can be classified as such with evidence. The tool combines this supplied coverage with local history and rejects a covered candidate while an eligible uncovered repository exists. It does not verify the supplied facts or check the separate cooldown, different-angle, or immediately-previous-repository rules: the workflow must enforce those independently. Retain the inventory evidence and report the eligible and uncovered counts.
